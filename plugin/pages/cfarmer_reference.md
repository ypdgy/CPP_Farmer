# C++ Farmer · C
**警告**: 这个 mod 用 vibe coding 写成，可能有 bug，遇到问题请到 GitHub 提 issue。

把代码窗口改名为以 `.c` 结尾，按运行键时会先编译成游戏本身的脚本再执行。
编译产物仍是游戏语言，所以操作数消耗、成就、科技树解锁与手写脚本完全一致。

报错时先看 [常见错误与函数调用](cfarmer_errors)。

## 支持什么

- 入口是 `main`，函数按返回类型声明，调用前不必声明
- `main` 会被展开成顶层代码（不包成函数），所以**开局不需要解锁「函数定义」也能跑**；
  自定义函数和 `struct` 才需要那个科技
- **没有 `cout` / 输出流**（那是 C++ 的写法），输出用 `printf(...)` 或 `print(...)`
- 类型：`int` `float` `double` `bool` `char` `void` `long` `short` `unsigned` `signed` `size_t`
- 语句：`if` / `else`、`for`、`while`、`do`、`break`、`continue`、`return`
- 数组 `int a[9]`、全局变量、`const`、`static`
- `struct` 与 `typedef`，两种写法都行：`struct Point { int x; };` 或 `typedef struct { int x; } Point;`
- `enum`，成员按 `名字` 使用，如 `Color_Red`
- `printf`，见下

## printf

`printf` 会在编译期展开成字符串拼接，占位符与参数在编译期逐个核对：

`printf("total=%d, ratio=%s\n", total, "ok");`

支持的占位符：`%d` `%i` `%u` `%f` `%s` `%c`，以及 `%%` 表示一个百分号。

**宽度与精度会被解析但不生效**：`%5.2f` 不会补齐 5 位、不会保留 2 位小数。数值按游戏自己的格式输出。需要固定格式时，先自己算好再打印。

`%c` 后面必须是字符字面量（如 `'A'`）；传整数会报错，因为游戏里没有「把 65 变成 A」这一步。

`%x` `%o` `%e` `%g` 这类占位符**会被拒绝**，而不是悄悄打印成十进制：游戏没有十六进制或科学计数法的输出，静默给出错误数字比报错更糟。

占位符比参数多、或参数比占位符多，都会直接报错并指出行号，不会打印出半截字符串。

## 标准头被忽略

`#include <stdio.h>`、`#include <stdbool.h>` 这类尖括号包含会被**整行忽略**，不需要删掉。
它们只是让编辑器不报错；游戏里没有标准库可链接。

自己写多文件时用引号包含：`#include "farm.c"` 会被编译成模块导入，被包含的文件必须是一个已存在的 `.c` 窗口。

## 不支持什么

- 指针、`malloc` / `free`、`memcpy`
- `switch` / `case` / `default`、`goto`、`sizeof`
- 位运算与位域、`union`
- 类、模板、命名空间、`std::vector` / `std::map` / `std::string`
- 多字符字符常量、宽字符、可变参数函数（`printf` 是编译器特例，自己写的 `...` 不行）

写成这些会得到带行号的明确报错，而不是静默出错。

## 与 C++ 的关系

`.c` 与 `.cpp` 共用同一个编译器。这意味着 `.c` 里其实也能用 `std::vector` 之类的 C++ 写法，
但**不推荐**：C 的意义是可移植的纯 C，混用只会让以后想搬走代码时更麻烦。

`.c` 窗口存成 `main.c`（不是 `main.c.py`），可以直接用 VS Code 打开存档目录编辑，
方法见外部编辑器说明页。

## 存档与备份

本模组不改 `save.json`、不解锁任何科技。但代码文件会参与游戏的保存流程，
自动存档会清理「不属于当前打开窗口」的代码文件。改文件、恢复备份前请先退出游戏。
